# HHHS 0.4.5 exclusive-host adoption checkpoint

Date: 2026-09-01

Candidate: `e68402fe3efe6a22212c804f84c038ee3838d499`

This is a downstream compatibility checkpoint, not an HHHS release
qualification and not a `v0.4.5` tag claim.

## Boundary adopted

- One `DurableReplicaHost` owns `MemoryStorage` and the asynchronous sink.
- No application-visible handle can prepare, publish, repair, or persist
  around that host.
- A cloneable memory control can inspect exact bytes and inject a deterministic
  test failure, but cannot write.
- External durability failure fences the host. Retry requires reopening the
  exact durable bytes; a fenced read is an error, never an empty projection.
- Public admissions and receiver-local projection checkpoints both use the
  host's prepare/persist-before-publish/finalize boundary.
- Browser durability uses `hhhs-web-browser::IndexedDbReplicaLog`, including
  its Web Lock writer lease and exact recovery state.
- Existing Hyperscope IndexedDB rows are imported non-destructively only when
  they form an exact valid transaction sequence. If old and new journals both
  exist, they must match byte-for-byte transaction encodings.
- Durable-project reactive conveniences that depended on an aliased storage
  writer were removed. Runtime FRP remains downstream of committed `AppStore`
  snapshots.
