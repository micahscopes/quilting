# HyperPatch architecture and compiler-cost boundary

`quilting_hyperpatch` is a small static vocabulary for asking different patch
families the same narrow question: what typed value does this typed parameter
denote, and was that finite evaluation defined? It is not a runtime algebra
interpreter, scene model, tessellator, or replacement for Rust Quilting.

## Static axes

A concrete kernel fixes four independent axes at compile time:

- the parameter domain and its coordinate representation;
- the codomain and its represented value;
- the family-specific controls and conditioning policy.

The current `QbTriangleKernel` is the first adapter. It maps barycentric
triangle parameters to Euclidean three-space through the existing
three-control quaternionic-Bezier evaluator. The adapter must be bit-identical
to that family evaluator; it does not replace the detailed QB differential,
conditioning, or permutation interfaces.

Later Clifford-Bezier kernels are peers of QB, not dependencies or disguised
QB control layouts. CGA and QCGA are representation or authoring choices, not
synonyms for hyperbolic space. Any actual hyperbolic implementation must name
its model, curvature, point admission, chart, metric, and isometry laws before
joining this interface.

## Compiler boundary

The Fe signature places `Controls`, `Domain`, `Codomain`, and `Policy` behind
kernel-associated types. An initial qualified return spelling,
`DenotationSample<<Self as HyperPatchKernel>::Codomain>`, appeared to fail with
a projection mismatch. The minimized upstream reproduction showed that the
failure comes from adjacent `<<` parsing, not projection normalization: adding
whitespace makes the same qualified type compile. Unfortunately `fe fmt`
removes that load-bearing whitespace and recreates the failure.

The checked-in API therefore uses the equivalent formatter-stable associated
projection `DenotationSample<Self::Codomain>`. It keeps the desired static API;
there is no ordinary-generic evaluator ABI, type erasure, or runtime tag. The
parser/formatter round-trip is an upstream bug with a standalone reproducer,
and release-profile compile timing remains a gate. A more elaborate GAT
reconstruction was observed to compile pathologically slowly, but it is not
needed for this interface and is not being substituted for the direct design.

## HyperPatch is not atlas selection

Quilting's static-dynamic LOD machinery remains separate. Rust builds a
canonical resident tessellation atlas and its seam-safe permutation metadata;
warm frames select precomputed LOD/permutation instances so tessellation looks
dynamic without rebuilding topology. HyperPatch specializes the arithmetic
evaluated over selected samples. It does not own atlas construction or per-frame
selection.

A bounded compile-time work-allocation vocabulary was prototyped, but it is not
part of this checkpoint. The current compiler rejects a module-constant record
when a Wasm export reads one scalar field from it, and compile-time assertions
over the record imposed a disproportionate release-check cost. Backend work
planning will return only after those compiler behaviors are resolved and an
independent host plan agrees with generated GPU execution.

## Evidence required for every kernel

Promotion beyond an experiment requires:

1. a separately written Rust f64/f32 oracle;
2. Fe/Wasm agreement;
3. generated WGSL execution and validation;
4. any claimed GLSL/WebGL2 path executed in that backend;
5. audits for operation count, live temporaries, generated bytes, compile
   latency, repeated-context stability, and context loss; and
6. no warm-frame readback, topology rebuild, or runtime family switch.

The first interactive extension should remain small: a paired QB/Clifford
patch lab with draggable controls and linkable state. Clifford curves are a
useful later GA widget, not part of the initial QB adapter checkpoint.

## Release evidence at the QB adapter checkpoint

All results below use Fe `c6ab98f222d5def80ad6d2bf6c99373666d6b48e`,
an optimized `target/release/fe`, Fe's `release` project profile, and Cargo
release artifacts. The one-time cold compiler build took 15m59s. A full Fe
workspace check then took 68.24s cold and 16.26s warm.

- artifact ABI without optional compiler features: 7/7;
- read-only Rust Quilting export and pool-width determinism: 11/11;
- O2 Fe/Wasm oracle, including bit-identical direct-QB/HyperPatch output:
  15/15;
- optimized Fe/Wasm plus generated WGSL on Vulkan llvmpipe: 18/18;
- strict release Clippy for the complete raster-oracle feature surface: green;
- regenerated fixtures and fixed raster source: byte-identical.

The O2 oracle's cold dependency/codegen build plus tests took 433.20s; an
uncontended checkpoint run executed the tests in 4.34s. The subsequent
SPIR-V/wgpu feature build plus GPU tests took 118.67s; test execution itself
took 7.23s. A final gate after adding the explicit undefined-case assertion
also passed 15/15, but ran under substantial unrelated host load and is not a
comparable timing sample. These are explicit build and test costs, not warm
runtime claims.

The parser/formatter reproduction passes and fails identically on the pinned
revision and clean Fe `6d26c910a25c8cc4d4428c861d77204c72e8d2bb`.
Upstream acknowledged the minimized report and plans a focused regression.
